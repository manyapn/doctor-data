# Doctor Data Aggregation Tool

A lightweight JavaScript tool that gathers public physician profile data, normalizes it into one profile per doctor, and displays the result in a static local UI.

## Run locally

Open the UI with cached seed data:

```bash
open index.html
```

Scrape fresh local data:

```bash
cd scraper
npm install
npm run install-browsers
npm test
npm run scrape
```

Then refresh `index.html`. The UI first tries `data/doctors.json`, which is generated by the scraper. If that file is missing, it falls back to `data/doctors.seed.json`.

## Current architecture

The project has three simple layers:

1. `scraper/scrape.js` collects raw source data from each seeded URL.
2. `scraper/normalizer.js` merges those raw source records into one clean profile shape.
3. `app.js` renders the normalized JSON in the browser.

Shared source configuration lives in `scraper/config.js`.

## Sources used

| Source | Current use |
| --- | --- |
| NPPES NPI Registry | Legal name, credentials, taxonomy, city, state |
| Healthgrades | Explicit aggregate patient review metadata, short profile description |
| Doximity | Education, affiliation when exposed, overview summary, publications and presentations |
| Vitals | Overview bio and affiliation when reachable, review metadata only when explicit aggregate review data exists |
| US News | Parser is implemented for overview and education, but this network blocks access |

## Data rules

- NPI is the base identity source for name, credentials, taxonomy, city, and state.
- Overview uses the longest usable summary from available sources.
- Patient Reviews include only explicit aggregate review metadata with a positive review or rating count.
- Scrape Status shows whether each seeded source page was reachable during the run.
- Each displayed source-derived field includes a direct source link where available.

## Known constraints

- Profile URLs are manually seeded. There is no automatic discovery step.
- US News blocks this environment. Direct Axios, curl, Node HTTPS, and Playwright tests failed with 403, timeout, reset, or HTTP/2 protocol errors. Still experimenting with how to access information.
- Vitals is inconsistent. Golive may load, while Marin and Hawkins often return 403.
- Doximity public pages expose only partial profile data unless logged in as a verified healthcare professional.
- Research scraping is intentionally conservative. It uses visible Doximity publication and presentation text and does not attempt to infer authorship from hidden or truncated records, but currently still misses some papers - current limitation that I'm working on.
- This is a short case-study project, not a production medical data pipeline.

## Scaling notes

For 1,000+ doctors:

- Use NPI registry search and pagination for discovery.
- Store raw source results separately from normalized profiles.
- Add a queue with per-source rate limits.
- Track `last_scraped_at` per source and scrape incrementally.
- Use a proxy or managed data provider for sources that block automated traffic.
- Add stronger identity matching with NPI numbers, cities, specialties, and profile URLs.
